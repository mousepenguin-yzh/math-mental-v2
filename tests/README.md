# 自動化測試基線

使用 Node.js 24 LTS，不需安裝套件：

```sh
npm test
```

也可以直接執行 `node --test tests/*.test.cjs`。目前沒有任何 npm 依賴，故不需要 `npm install`、lockfile 或 CI 安裝步驟。

## 測試方式及範圍

- `helpers/app.cjs`：從正式 `index.html` 讀取兩段 inline script，原封不動在隔離的 `node:vm` context 執行。不複製、不改寫正式函式。每個案例有獨立狀態、固定種子的 LCG 隨機源、最小 DOM 替身，以及同步可推進的 `setTimeout` / `clearTimeout` / `Date.now`。
- `generators.test.cjs`：四種挑戰各自產生 10、20、30 題；確認固定種子可重現。種子 `0x5eed` 依序對挑戰 1–4 各驗證 1,200 題（共 4,800 題）。失敗訊息包含種子、挑戰、題目索引與題型。從題面讀取運算元，獨立驗算四則、分數、指數、方程式、比例式、乘法公式、平方、指數反查、因數、分數小數互換與畢氏邊長，並核對訂正答案及欄位。覆蓋檢查要求全部 17 種標籤、12 種比例式分支、24 種畢氏三元組/倍率/求邊組合及四種指數括號/次方組合均出現。
- `answers-flow.test.cjs`：執行真正的 `checkAnswer`、`loadQuestion`、`startGame` 等函式。測試正誤、負數、小數、零、空值、等值分數、負分母、零分母、第二階段所有欄位及交換群組。檢查加星、錯題只記一次、600ms 訂正與 1500ms 換題邊界、進度、混合作答結果、百分比與耗時。
- `known-bugs.test.cjs`：實際執行下表的重現步驟，斷言**預期正確行為**，以 Node 內建 `{ todo: '原因' }` 管理目前失敗，不把 Bug 當作通過規格。

## CI 與限制

`.github/workflows/test.yml` 在 PR 與 main push 時，以單一 Ubuntu job、Node 24 執行相同的 `npm test`。權限只有 `contents: read`，checkout 不保留憑證，兩個官方 action 均固定完整 commit SHA 並註明版本。Node 固定受支援的 LTS 主版本，允許接收修補更新；升級 action 時請核對官方標籤 SHA。沒有部署、瀏覽器下載、第三方測試框架或版本矩陣。

這是邏輯與狀態轉場測試，不是瀏覽器 E2E。DOM 替身只支援測試所需的操作；不驗證 CSS、版面、Canvas 像素、CDN 載入、捲動與焦點在真實裝置的表現。產生器抽樣固定且有主要分支覆蓋檢查，但不是所有隨機排列的窮舉；平方反查只驗證正根是合法解，負根題意與錯誤提示另外列為 TODO。若正式腳本結構或 DOM API 需求改變，應相應調整替身，避免擴充成通用 DOM 框架。
