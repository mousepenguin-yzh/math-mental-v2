# 根式精確答案接口（PR A）

本階段提供純數學核心與既有作答流程的安全分派；沒有新關卡、出題器、根號鍵或輸入編輯器。正式五關仍使用原字串答案及原判定路徑；BUG-05～07 未改動。

## 題目答案規格

`stage1Ans` / `stage2Ans` 的每個欄位可保留舊字串，或明確使用下列物件：

```js
{ type: 'radical', expected: { coefficient: 2, radicand: 5 }, form: 'simplest' }
{ type: 'integer', expected: 4 }
```

根式表示 `coefficient × √radicand`。預期值必須已標準化：非零根式的被開方數不含平方因數；整數使用 `radicand: 1`；零固定為 `{ coefficient: 0, radicand: 1 }`。根號代表非負平方根，負號在係數。未來正邊長題設定正的預期值即可拒絕負答案；本型別不表示方程式的多解集合。

`form` 必須明訂為 `simplest` 或 `equivalent`。根式專項的最終答案使用 `simplest`；`equivalent` 留給明確只要求等值的欄位，不應用它繞過最簡要求。未知型別、錯誤政策或非標準化預期值一律回傳 `invalid-spec`，不回退至舊數值解析。

## 純函式

- `parseRadicalAnswer(raw)`：回傳 `{ ok: true, coefficient, radicand, hasRadical }`，或 `{ ok: false, reason }`。保留是否實際寫出根號，供最簡形式判定。
- `normalizeRadical(value)`：回傳 `{ coefficient, radicand }`；無效組件或化簡後超界會拋出 `RangeError`。採整數平方因數抽取，無浮點近似比較。
- `validateTypedAnswer(raw, spec)`：UI 及判定流程的入口；捕捉上述範圍錯誤，回傳下表結果。沒有 DOM 或計分副作用。

| status | 意義 | accepted |
| --- | --- | --- |
| `correct` | 數值正確且最簡 | `true` |
| `equivalent-not-simplest` | 等值但未最簡 | 僅 `form: 'equivalent'` 為 `true` |
| `incorrect` | 合法但數值不相等 | `false` |
| `invalid` | 輸入或規格無法判定 | `false` |

合法結果另有 `equivalent`、`simplest`；根式另有標準化的 `value`。`invalid` 使用 `reason`：`incomplete`（尚未填完）、`syntax`（非法或本版不支援的語法）、`limit`（超出安全界線）、`invalid-spec`（題目設定錯誤）。這些 reason 不能被合併為一般數學錯誤。

## 語法與安全界線

僅接受 `-?digits` 或 `-?[digits]√digits`。首尾空白可忽略，Unicode 負號 `−` 轉成 ASCII `-`；前導零及明寫係數 1 不視為數學錯誤。內部空白不刪除，不接受正號、分數、小數、科學記號、變數、運算式或括號。

空值、單一負號、缺少被開方數的根式（如 `2√`）為 `incomplete`；`√-2`、`2√3abc`、`2√3+3√3` 等為 `syntax`。`√0`、`0√5`、`√16` 可以求值，但須寫為 `0`、`0`、`4` 才算最簡；`1√5` 與 `√5` 都算最簡。

`exactAnswerLimits` 為凍結設定：

- 原始輸入長度最多 32 個 UTF-16 code units，先檢查長度再 trim。
- 原始及標準化係數絕對值最多 1,000,000,000；嚴格整數欄位同上。
- 被開方數範圍 0～1,000,000。
- 僅接受安全整數；例如 `1000000√1000000` 可判定，`1000001√1000000` 的標準化係數超界，回傳 `limit`。

以上是運算與資源界線，不是題目難度規則。支援 `√450 = 15√2`、`√675 = 15√3`、`√800 = 20√2`、`√980 = 14√5`。未來題庫可用 1～20 的平方數與經挑選的小平方自由數相乘建構，依結構與步驟分級，本 PR 不生成題目。

## 作答整合與後續 UI 契約

`checkAnswer()` 先處理型別化欄位，再執行未改動的舊字串判定。型別化欄位不經過 `_num` / `_den` 分數配對或 `parseFloat()`；V1 不支援含型別化欄位的 `interchangeableGroups`，遇到此配置會停止判定並提示設定錯誤。

根式及嚴格整數可以與舊字串欄位出現在同一階段，成功仍要求所有欄位通過。原本的作答鎖定、600ms 訂正、1500ms 換題、錯題去重與生命週期清理保留。

- 有型別化欄位未完成或非法時，先提示修正，保持當前階段、答案與首次資格，不排定訂正。非法格式暫採同樣的非扣分處理；未擴充診斷統計。
- 全部欄位數值正確、只剩最簡形式未完成時，留在目前階段；第一階段設 `firstTry = false`。重送不重複記錯、不展開訂正；之後完成也不補發首次星星。
- 若另有數值錯誤欄位，走原本錯誤／訂正流程。純函式仍能逐欄回傳精確原因，後續 UI 可據此呈現。
- 原有結果頁以總題數減星星數計算「引導題數」；因此未最簡後修正的無星題也歸入此數字。本 PR 不另改報表分類，後續 UI 若需區分訂正展開次數，須新增獨立統計。

後續鍵盤應依欄位型別限制按鍵，並將原始文字傳入判定器；**不可先化簡再判定**，否則會丟失學生是否完成化簡的資訊。不要用 `parseFloat`、`parseInt`、浮點容差或顯示字串代替此接口。顯示內容需安全渲染；保留 `canAnswer()` 防護。實際輸入寬度與長度須涵蓋題庫需要，不能沿用十字元限制而無驗收。
